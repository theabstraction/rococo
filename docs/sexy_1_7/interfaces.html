Interfaces, classes and factories

Objects are classes behind interfaces. Script code holds interface references only, gets objects from factories, and the objects are reference counted.

Interface, class, factory

An interface lists method signatures. A class names the interfaces it implements and supplies a method for each. A factory is the only way to create an instance: it is a public function that runs construct on a class and returns the interface. Code outside the factory never names the class.

Interfaces and factories need a namespace for their public names, here Zoo.

Sexy
(namespace Zoo)
(using Sys.Type)

(interface Zoo.IAnimal
    (Legs -> (Int32 count))
    (Speak (IStringBuilder sb) -> )
)

(class Dog (implements Zoo.IAnimal))
(method Dog.Construct : )
(method Dog.Legs -> (Int32 count): (count = 4))
(method Dog.Speak (IStringBuilder sb) -> : (sb "Woof"))

(class Bird (implements Zoo.IAnimal))
(method Bird.Construct : )
(method Bird.Legs -> (Int32 count): (count = 2))
(method Bird.Speak (IStringBuilder sb) -> : (sb "Tweet"))

(factory Zoo.NewDog Zoo.IAnimal : (construct Dog))
(factory Zoo.NewBird Zoo.IAnimal : (construct Bird))

(function Main -> (Int32 result):
    (Zoo.IAnimal rex (Zoo.NewDog))
    (Zoo.IAnimal tweety (Zoo.NewBird))
    (IStringBuilder sb = (Sys.Type.NewStringBuilder 64))
    (rex.Speak sb)
    (tweety.Speak sb)
    (Sys.Print sb)
    (result = (rex.Legs - tweety.Legs) + 1)
)
C++20
#include <cassert>
#include <memory>
#include <string>

struct IAnimal
{
    virtual ~IAnimal() = default;
    virtual int Legs() const = 0;
    virtual void Speak(std::string& sb) const = 0;
};

namespace
{
    struct Dog final : IAnimal
    {
        int Legs() const override { return 4; }
        void Speak(std::string& sb) const override { sb += "Woof"; }
    };

    struct Bird final : IAnimal
    {
        int Legs() const override { return 2; }
        void Speak(std::string& sb) const override { sb += "Tweet"; }
    };
}

std::unique_ptr<IAnimal> NewDog() { return std::make_unique<Dog>(); }
std::unique_ptr<IAnimal> NewBird() { return std::make_unique<Bird>(); }

int main()
{
    auto rex = NewDog();
    auto tweety = NewBird();
    std::string sb;
    rex->Speak(sb);
    tweety->Speak(sb);
    assert(sb == "WoofTweet");
    assert(rex->Legs() - tweety->Legs() + 1 == 3);
}

Result Main returns 3 · prints WoofTweet

Defining the interface from the class

For a class with one interface, defines creates the interface from the class's methods, so you do not write the method list twice.

Sexy
(namespace Zoo)

(class Robot (defines Zoo.IRobot)
    (Int32 arms)
)
(method Robot.Construct (Int32 arms): (this.arms = arms))
(method Robot.Arms -> (Int32 count): (count = this.arms))
(method Robot.AddArm -> : (this.arms += 1))

(factory Zoo.NewRobot Zoo.IRobot (Int32 arms): (construct Robot arms))

(function Main -> (Int32 result):
    (Zoo.IRobot robby (Zoo.NewRobot 5))
    (robby.AddArm)
    (result = robby.Arms)
)
Python 3
class Robot:
    def __init__(self, arms: int):
        self._arms = arms

    def arms(self) -> int:
        return self._arms

    def add_arm(self) -> None:
        self._arms += 1

robby = Robot(5)
robby.add_arm()
assert robby.arms() == 6

Result Main returns 6

Missing methods are compile errors

A class that does not implement every method of its interface is rejected when the script compiles, as an abstract class is rejected in C++ only when you try to instantiate it.

Sexy
(namespace Zoo)

(interface Zoo.IAnimal
    (Legs -> (Int32 count))
    (Wings -> (Int32 count))
)

(class Dog (implements Zoo.IAnimal))
(method Dog.Construct : )
(method Dog.Legs -> (Int32 count): (count = 4))

(factory Zoo.NewDog Zoo.IAnimal : (construct Dog))

(function Main -> (Int32 result):
    (result = 1)
)
C++20 (does not compile)
// Expected NOT to compile: g++ reports that Dog is abstract because Wings is not overridden.
struct IAnimal
{
    virtual ~IAnimal() = default;
    virtual int Legs() const = 0;
    virtual int Wings() const = 0;
};

struct Dog : IAnimal
{
    int Legs() const override { return 4; }
};

int main()
{
    Dog d;    // error: cannot declare variable 'd' to be of abstract type 'Dog'
    return d.Legs();
}

Error Expecting method named 'Dog.Wings' inside source module

Null objects

An interface variable that has not been assigned is not null in the C++ sense. It refers to a built-in null object whose methods do nothing and return zero, false or another null object. Test for a real object with (x ?).

Sexy
(namespace Zoo)

(interface Zoo.IAnimal
    (Legs -> (Int32 count))
)

(function Main -> (Int32 result):
    (Zoo.IAnimal nobody)            // never assigned: a null object
    (Int32 legs = nobody.Legs)              // returns 0, does not crash
    (if (nobody ?) (result = 1) else (result = 100 + legs))
)
Python 3
nobody = None
try:
    legs = nobody.legs()          # AttributeError: 'NoneType' object has no attribute 'legs'
    raise SystemExit("unreachable")
except AttributeError:
    pass

Result Main returns 100

When a silent zero would hide a bug, mark the interface (attribute essential). Calling a method through an unassigned reference then throws.

Sexy
(namespace Zoo)

(interface Zoo.IAnimal (attribute essential)
    (Legs -> (Int32 count))
)

(function Main -> (Int32 result):
    (Zoo.IAnimal nobody)
    (result = nobody.Legs)                  // throws: essential interfaces have no null object
)

Error IAnimal.Legs: null reference

Deterministic destruction

Objects are reference counted. When the last reference goes, here at the end of UseTorch, the object's Destruct method runs immediately. There is no collector and no finaliser queue, so you can tie resources to object lifetime as you would with RAII in C++.

Sexy
(namespace Zoo)

(global Int32 destroyed = 0)

(class Torch (defines Zoo.ITorch))
(method Torch.Construct : )
(method Torch.Light -> : )
(method Torch.Destruct -> :
    (Int32 n)
    (global destroyed -> n)
    (n += 1)
    (global destroyed <- n)
)
(factory Zoo.NewTorch Zoo.ITorch : (construct Torch))

(function UseTorch -> :
    (Zoo.ITorch t (Zoo.NewTorch))
    (t.Light)
)                                           // last reference released here

(function Main -> (Int32 result):
    (UseTorch)
    (Int32 afterCall)
    (global destroyed -> afterCall)
    (UseTorch)
    (Int32 afterTwo)
    (global destroyed -> afterTwo)
    (result = (afterCall * 10) + afterTwo)
)
Lua 5.4
-- Lua 5.4: a to-be-closed variable gives deterministic cleanup; __gc alone would run whenever the collector decides
local destroyed = 0

local Torch = {}
Torch.__index = Torch
Torch.__close = function() destroyed = destroyed + 1 end

local function NewTorch() return setmetatable({}, Torch) end
function Torch:Light() end

local function UseTorch()
  local t <close> = NewTorch()
  t:Light()
end                                   -- __close runs here

UseTorch()
local afterCall = destroyed
UseTorch()
assert(afterCall * 10 + destroyed == 12)

Result Main returns 12

Casting between interfaces

A class can implement several interfaces. cast gives you another interface on the same object.

Sexy
(namespace Zoo)

(interface Zoo.IWalker
    (Legs -> (Int32 count))
)
(interface Zoo.ISwimmer
    (Fins -> (Int32 count))
)

(class Frog (implements Zoo.IWalker)(implements Zoo.ISwimmer))
(method Frog.Construct : )
(method Frog.Legs -> (Int32 count): (count = 4))
(method Frog.Fins -> (Int32 count): (count = 2))

(factory Zoo.NewFrog Zoo.IWalker : (construct Frog))

(function Main -> (Int32 result):
    (Zoo.IWalker w (Zoo.NewFrog))
    (cast w -> Zoo.ISwimmer s)
    (Int32 legs = w.Legs)
    (Int32 fins = s.Fins)
    (result = (legs * 10) + fins)
)
C++20
#include <cassert>
#include <memory>

struct IWalker { virtual ~IWalker() = default; virtual int Legs() const = 0; };
struct ISwimmer { virtual ~ISwimmer() = default; virtual int Fins() const = 0; };

struct Frog final : IWalker, ISwimmer
{
    int Legs() const override { return 4; }
    int Fins() const override { return 2; }
};

int main()
{
    std::unique_ptr<IWalker> w = std::make_unique<Frog>();
    auto* s = dynamic_cast<ISwimmer*>(w.get());   // nullptr if the object does not implement it
    assert(s != nullptr);
    assert(w->Legs() * 10 + s->Fins() == 42);
}

Result Main returns 42

Getter calls such as s.Fins work as values on their own, but the compiler rejects them as the right operand next to a compound expression, as in ((w.Legs * 10) + s.Fins). Bind them to locals first, as the example does.
