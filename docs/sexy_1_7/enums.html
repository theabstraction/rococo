Strong types and enums

A strong type wraps a primitive so that values of different meaning cannot be mixed. Enums and flags are strong types with named values.

Strong types

(strong CustomerId (Int32)) declares a type with an Int32 inside. A literal can initialise it; reading the number back needs .Value.

Sexy
(strong CustomerId (Int32))

(function Main -> (Int32 result):
    (CustomerId id = 72)
    (result = id.Value)
)
C++20
#include <cassert>

// The usual C++ stand-in for a strong type: a one-member struct with an explicit constructor
struct CustomerId { int value; explicit CustomerId(int v): value(v) {} };
struct OrderId { int value; explicit OrderId(int v): value(v) {} };

void Cancel(OrderId) {}

int main()
{
    CustomerId id{ 72 };
    assert(id.value == 72);
    // Cancel(id);           // error: no conversion from CustomerId to OrderId
    // int raw = id;         // error: no conversion to int
    Cancel(OrderId{ 7 });
}

Result Main returns 72

A strong type does not convert to its primitive, or to another strong type with the same primitive. Both of these fail:

Sexy
(strong CustomerId (Int32))

(function Main -> (Int32 result):
    (CustomerId id = 72)
    (result = id)
)

Error Type mismatch trying to assign [CustomerId id] to [Int32 result]

Sexy
(strong CustomerId (Int32))
(strong OrderId (Int32))

(function Cancel (OrderId order) -> :
)

(function Main -> (Int32 result):
    (CustomerId id = 72)
    (Cancel id)
)

Error While compiling function Main: Pushing argument to a function rejected. (OrderId order) was strongly-typed but the supplied type was CustomerId,which is the correct underlying type but not directly convertible.

Enums

An enum adds named values to a strong type. Unvalued names count up from the previous one. There are two ways to write a constant:

  • .Wednesday takes its type from the target, so it works wherever the target type is known: assignment, arguments, comparisons, struct fields and container calls.
  • Day@Friday names the type explicitly. The type must be exactly the target type.

The alias line publishes the type as Sys.Type.Day; the enum directive uses that public name.

Sexy
(strong Day (Int32))
(alias Day Sys.Type.Day)

(enum Sys.Type.Day
    (Monday 1)
    Tuesday
    Wednesday
    Thursday
    Friday
)

(function DaysToWeekend (Day d) -> (Int32 n):
    (Int32 v = d.Value)
    (n = 6 - v)
)

(function Main -> (Int32 result):
    (Day today = .Wednesday)          // type comes from the target
    (Day payday = Day@Friday)         // or name the type explicitly
    (Int32 w = today.Value)
    (Int32 p = payday.Value)
    (Int32 n = (DaysToWeekend .Monday))
    (result = (w * 100) + (p * 10) + n)
    (if (today == .Wednesday) (result -= 4))
)
Python 3
from enum import IntEnum

class Day(IntEnum):
    MONDAY = 1
    TUESDAY = 2
    WEDNESDAY = 3
    THURSDAY = 4
    FRIDAY = 5

def days_to_weekend(d: Day) -> int:
    return 6 - d          # IntEnum is an int, so this needs no .value

today = Day.WEDNESDAY
payday = Day.FRIDAY
result = today * 100 + payday * 10 + days_to_weekend(Day.MONDAY)
if today == Day.WEDNESDAY:
    result -= 4
assert result == 351

Result Main returns 351

Unlike Python's IntEnum, a Sexy enum is not a number. Arithmetic needs .Value, and the compiler does not yet accept d.Value directly inside an arithmetic expression, so bind it to a local first.

A misspelt constant is reported when the function body is compiled, on its first call and before any of it runs. Python raises only when the line itself runs.

Sexy
(strong Day (Int32))
(alias Day Sys.Type.Day)
(enum Sys.Type.Day (Monday 1) Tuesday Wednesday Thursday Friday)

(function Main -> (Int32 result):
    (Day d = .Fryday)
)
Python 3
from enum import IntEnum

class Day(IntEnum):
    MONDAY = 1
    FRIDAY = 5

def main():
    return Day.FRYDAY     # AttributeError, raised only when main() runs

try:
    main()
    raise SystemExit("unreachable")
except AttributeError:
    pass

Error Cannot identify 'Fryday' as an enum

Flags

flags declares values that must be bitwise distinct, so they can be combined with | and tested with &. append writes the names of the set flags to a string builder.

Sexy
(using Sys.Type)

(strong Alignment (Int32))
(alias Alignment Sys.Type.Alignment)

(flags Sys.Type.Alignment
    (None 0)
    (Top 1)
    (Left 2)
    (Bottom 4)
    (Right 8)
)

(function Main -> (Int32 result):
    (Alignment a = (Alignment@Top | Alignment@Right))
    (IStringBuilder sb = (NewStringBuilder 64))
    (append sb a)                      // appends "Top Right"
    (Sys.Print sb)
    (if (a & .Left) (result = 1000))
    (result += a.Value)
)
Python 3
from enum import IntFlag

class Alignment(IntFlag):
    NONE = 0
    TOP = 1
    LEFT = 2
    BOTTOM = 4
    RIGHT = 8
    TOP_LEFT = 3          # allowed in Python; Sexy's (flags ...) rejects overlapping values

a = Alignment.TOP | Alignment.RIGHT
names = [m.name for m in (Alignment.TOP, Alignment.LEFT, Alignment.BOTTOM, Alignment.RIGHT) if m in a]
assert " ".join(names) == "TOP RIGHT"
result = 1000 if a & Alignment.LEFT else 0
result += a
assert result == 9

Result Main returns 9 · prints Top Right

Combinations cannot be declared as flags. Python allows them; Sexy rejects them when the script compiles:

Sexy
(strong Alignment (Int32))
(alias Alignment Sys.Type.Alignment)

(flags Sys.Type.Alignment
    (Top 1)
    (Left 2)
    (TopLeft 3)
)

(function Main -> (Int32 result):
    (result = 1)
)

Error flags Alignment: TopLeft (3 / 0x3) shares bits with Top (1 / 0x1). Every flag must be bitwise distinct, so combinations cannot be declared

Iterating over an enum

foreach-enum visits each value in declaration order. name is an IString and value is an Int64. The loop is unrolled at compile time, one copy of the body per value; break and continue work as usual.

Sexy
(using Sys.Type)

(strong Day (Int32))
(alias Day Sys.Type.Day)
(enum Sys.Type.Day (Monday 1) Tuesday Wednesday Thursday Friday)

(function Main -> (Int32 result):
    (IStringBuilder sb = (NewStringBuilder 128))
    (Int64 total = 0)
    (foreach-enum name value in Day:
        (sb name)
        (sb " ")
        (total = (total + value))
    )
    (Sys.Print sb)                     // Monday Tuesday Wednesday Thursday Friday
    (result = (Sys.Maths.I64.ToInt32 total))
)
Python 3
from enum import IntEnum

class Day(IntEnum):
    MONDAY = 1
    TUESDAY = 2
    WEDNESDAY = 3
    THURSDAY = 4
    FRIDAY = 5

names = []
total = 0
for d in Day:             # a runtime loop; Sexy unrolls foreach-enum at compile time
    names.append(d.name)
    total += d
assert " ".join(names) == "MONDAY TUESDAY WEDNESDAY THURSDAY FRIDAY"
assert total == 15

Result Main returns 15 · prints Monday Tuesday Wednesday Thursday Friday

Parsing a name

fromstring looks up a value by its exact, case-sensitive name and reports success in a Bool. The -> ok part is mandatory, so a failed parse cannot go unnoticed.

Sexy
(strong Day (Int32))
(alias Day Sys.Type.Day)
(enum Sys.Type.Day (Monday 1) Tuesday Wednesday Thursday Friday)

(function Main -> (Int32 result):
    (Bool ok)
    (Day d = fromstring "Friday" -> ok)
    (Int32 v = d.Value)
    (if ok (result = v * 10))
    (Day e = fromstring "friday" -> ok)  // case-sensitive: no match
    (if (not ok) (result += 1))
)
Python 3
from enum import IntEnum

class Day(IntEnum):
    MONDAY = 1
    FRIDAY = 5

result = 0
d = Day.__members__.get("FRIDAY")       # Day["FRIDAY"] would raise KeyError on a miss
if d is not None:
    result = d * 10
if Day.__members__.get("friday") is None:  # case-sensitive, as in Sexy
    result += 1
assert result == 51

Result Main returns 51
